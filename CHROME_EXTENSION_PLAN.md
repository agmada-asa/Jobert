# Jobert Chrome Extension: Technical Plan

## 1. Overview
The Jobert Chrome Extension will extend the "collaborative, privacy-first application assistant" into the browser. It allows users to apply for jobs directly on company portals (Lever, Greenhouse, Workday, etc.) while leveraging their existing Jobert Knowledge Base (CV + Notion).

## 2. Core Features
- **Webpage Parsing:** Detect and extract job descriptions and application form questions.
- **Knowledge Base Integration:** Access user's stored CV and Notion KB via the Jobert backend.
- **AI-Powered Response Generation:** Use Gemini to generate tailored answers for form questions.
- **Form Auto-fill:** Inject generated responses directly into the webpage elements.
- **Job Tracking:** Automatically save the application details and status to the Supabase database.
- **SPA & Multi-step Support:** Handle dynamic forms and multi-page application flows.

## 3. Architecture

### Frontend (Chrome Extension)
- **Manifest V3:** Modern extension standard.
- **Background Service Worker:** Handles API communication and state management.
- **Content Scripts:** Performs DOM inspection, question extraction, and form injection.
- **Side Panel / Popup UI:** Provides the user interface for triggering the AI and reviewing answers.
- **Shadow DOM:** Used for the UI to prevent style leakage from the host website.

### Backend (FastAPI - Existing)
- **New Endpoints:**
    - `GET /user/profile`: Returns the user's KB context (CV text + Notion facts).
    - `POST /generate-answers`: Accepts job context and returns AI-generated responses.
    - `POST /applications`: Saves a new job application record.
- **Authentication:** 
    - A "Magic Link" or "Auth Code" generated by the Telegram bot to link the browser extension to the user's account.

## 4. Implementation Details

### 4.1. Question Extraction (Content Script)
- **Heuristics:** Identify labels, placeholders, and `aria-label` attributes associated with `input`, `textarea`, and `select` elements.
- **Context Gathering:** Capture the surrounding text and the job description to provide the LLM with full context.

### 4.2. Form Injection
- **Mapping:** Match LLM-generated answers to DOM elements using a mapping of question text to element IDs/selectors.
- **Simulating Input:** Trigger `input` and `change` events after setting values to ensure SPA frameworks (React/Vue/Angular) register the changes.

### 4.3. Handling Multi-page Applications
- **State Persistence:** Store the "Application Session" in `chrome.storage.local`.
- **MutationObserver:** Monitor the DOM for changes to detect when a new "page" or "step" of the form has loaded.

### 4.4. Security & Privacy
- **BYOK (Bring Your Own Key):** Continues to use the user's Gemini API key.
- **Encrypted Communication:** All sensitive data transmitted over HTTPS.
- **Selective Scoping:** Extension only activates on known job portal domains or when manually triggered.

## 5. Development Phases

### Phase 1: Setup & Authentication
- Boilerplate for Manifest V3 extension.
- Implementation of the "Connect Extension" flow via the Telegram bot.
- Basic Side Panel UI.

### Phase 2: Page Parsing & Knowledge Retrieval
- Content script for extracting form fields.
- Backend endpoint to aggregate CV + Notion KB data.
- UI to display "Found Questions".

### Phase 3: AI Integration & Auto-fill
- Integration with Gemini (v3 Flash) for answer generation.
- Logic for injecting answers into the DOM.
- Support for various input types (text, radio, checkboxes, selects).

### Phase 4: Job Tracking & Multi-page support
- Integration with the `applications` table in Supabase.
- Logic for handling "Next" buttons and dynamic form updates.
- Final testing on major job portals (Greenhouse, Lever, etc.).

## 6. Success Criteria
- User can link extension to their Jobert account in < 30 seconds.
- Extension accurately identifies > 90% of form questions on Lever/Greenhouse.
- Auto-fill works without breaking SPA form state.
- Application status is correctly reflected in the Jobert dashboard/Notion.
